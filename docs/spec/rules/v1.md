# Rules v1

Status: **draft**. It is frozen once the first implementation passes all
vectors and we tag it.

Rules version `R = 1`. This spec defines everything that must be identical
across implementations for a given game descriptor `(R, mode, seed)`: the
item sequence, the time limits and the scoring. Presentation (palettes,
words, animations) is informative and lives in the appendix and in
`docs/design/`.

Conformance vectors: `docs/spec/test-vectors/rules/v1/`.

## 1. Notation

- `u64`: unsigned 64-bit integer. All arithmetic on `u64` wraps modulo 2⁶⁴.
- `>>`: logical shift right. `^`: bitwise XOR.
- Integer division `a / b` truncates toward zero. All operands here are
  non-negative.
- Item and round numbers `n` start at **1**.
- No floating point is used anywhere in this spec.

## 2. PRNG: SplitMix64

```
state: u64 := seed

next() -> u64:
    state := state + 0x9E3779B97F4A7C15
    z := state
    z := (z ^ (z >> 30)) * 0xBF58476D1CE4E5B9
    z := (z ^ (z >> 27)) * 0x94D049BB133111EB
    return z ^ (z >> 31)
```

### 2.1 Bounded integers: `below(k)` for `1 ≤ k ≤ 2³²`

This is unbiased rejection sampling:

```
below(k) -> integer in [0, k):
    threshold := (2⁶⁴ − k) mod k       // equivalently: (0 − k) mod k in u64
    loop:
        x := next()
        if x ≥ threshold: return x mod k
```

### 2.2 Value excluding one: `belowExcept(k, e)` for `k ≥ 2`, `0 ≤ e < k`

Returns a uniform value in `[0, k) \ {e}` using exactly one `below` call:

```
belowExcept(k, e):
    r := below(k − 1)
    return r ≥ e ? r + 1 : r
```

### 2.3 Coin: `coin()`

```
coin() := below(2) == 1
```

The PRNG is created once per game from the descriptor's seed. Calls happen
**only** in the order given in §4, item after item. Player answers never
influence PRNG calls, so every player sees the identical sequence whatever
they answer. A generator may therefore precompute items ahead of time.

## 3. Colour slots and pool

Logic uses abstract **colour slots** `0..7`. Each slot has an ink colour and
a word (appendix A). Correctness is decided only on slots, never on words or
RGB values.

The **pool** is the set of slots `0..p−1` that may appear. Its size `p`
grows with the item/round number `n`:

```
poolSize(n, T) := 4 + |{ t ∈ T : t ≤ n }|
```

with growth thresholds per mode:

| mode | `T` |
|---|---|
| classic, chrono, find | `{20, 30, 40, 50}` |
| tap | `{6, 11, 16, 21}` |

So the pool has 4 colours at the start and 8 at most.

## 4. Modes

Mode identifiers (also used by game codes and multiplayer messages):

| id | name |
|---|---|
| 1 | `classic` |
| 2 | `chrono` |
| 3 | `find` |
| 4 | `tap` |

### 4.1 Word items: classic (1), chrono (2), find (3)

An item is `(ink, word)`, two slots. The item is **true** iff
`ink == word`. Generating item `n` with `p := poolSize(n, T)`:

```
if n == 1:  ink := below(p)
else:       ink := belowExcept(p, prevInk)      // never the same ink twice in a row

if mode == find:
    word := belowExcept(p, ink)                  // always false; no coin drawn
else:
    if coin(): word := ink
    else:      word := belowExcept(p, ink)

prevInk := ink
```

`prevInk` is always smaller than `p`, because the pool never shrinks.

### 4.2 Card rounds: tap (4)

A round has 4 cards `(ink, word)` with **pairwise distinct inks**. Exactly
one card is true. Generating round `n` with `p := poolSize(n, T)`:

```
a := [0, 1, …, p−1]
for i in 0..3:                    // partial Fisher–Yates
    j := i + below(p − i)
    swap(a[i], a[j])
inks := a[0..3]                   // card order = display order (positions 0..3)

trueCard := below(4)
for c in 0..3:
    if c == trueCard: word[c] := inks[c]
    else:             word[c] := belowExcept(p, inks[c])
```

Words of the false cards may repeat or name inks that other cards show.

## 5. Time limits

Times are in integer milliseconds. A limit starts when the item or round is
**fully shown**. An answer counts only if it comes at a time `t < limit`.
At `t ≥ limit` it is a timeout.

### 5.1 Per-item limit: classic, find

```
base(n) := 6000  if n == 1
           4000  if n < 10
           3000  if n < 20
           2500  if n < 30
           2000  if n < 40
           1600  otherwise

itemLimit(n) := max(250, base(n) · (300 − n) / 300)       // for n ≥ 300 the second term is ≤ 0
```

### 5.2 Per-round limit: tap

```
roundLimit(n) := max(250, 2000 − 10 · (n − 1))
```

### 5.3 Total limit: chrono

The whole game lasts `30000` ms, measured from the first item being shown.
There is no per-item limit.

## 6. Answers, scoring, end of game

| mode | the player answers… | correct when |
|---|---|---|
| classic | TRUE or FALSE | the answer equals `ink == word` |
| chrono | TRUE or FALSE | the answer equals `ink == word` |
| find | a colour slot from the pool (`0..p−1`) | the chosen slot `== word` |
| tap | a card position `0..3` | the chosen card is `trueCard` |

- **classic, find, tap**: a correct answer adds +1 to the score and moves to
  `n + 1`. A wrong answer or a timeout **ends** the game.
  `score = n − 1`, where `n` is the failed item or round.
- **chrono**: every answer moves to `n + 1`. A correct answer adds +1. A wrong
  answer subtracts 1, but the score never goes below 0. The game ends when
  the total limit is reached. The item shown at that moment is unanswered.

A game result consists of `score` and `reached`. `reached` is the number of
the item or round that was failing or unanswered at the end. Both are
non-negative integers.

## Appendix A (informative): presentation

Default palettes. Implementations may refine shades for contrast, as long as
slots keep their identity.

| slot | normal ink | normal word | colour-blind ink | colour-blind word |
|---|---|---|---|---|
| 0 | `#f1c40f` | yellow | `#ffd71d` | yellow |
| 1 | `#e74c3c` | red | `#f95341` | red |
| 2 | `#3498db` | blue | `#0a88dc` | blue |
| 3 | `#2ecc71` | green | `#18df6c` | green |
| 4 | `#e67e22` | orange | `#04e5e3` | cyan |
| 5 | `#9b59b6` | purple | `#cfb891` | beige |
| 6 | `#ff89e5` | pink | `#8b0eaa` | purple |
| 7 | `#a67235` | brown | `#7d4f1b` | brown |

Words are localised. Palette and language are per-player settings and do
not affect the logic.

Suggested feel:
- a 3-2-1-GO countdown of 1 s per step before the first item;
- a ring timer around the word that drains over `itemLimit(n)`, with its
  stroke getting thinner with `n`;
- short vibration on failure.
